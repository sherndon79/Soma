# Soma Principles

Status: initial principles

These principles are provisional, but they should guide early Soma design and review.

## Consent

Consent must be explicit, scoped, and revocable.

Presence in a workspace is not consent to every perception channel, memory write, remote call, or
tool action. Stronger capabilities require stronger consent.

## Disclosure

Soma should make its current mode visible.

Participants should know whether Soma is text-only, audio-aware, visual-aware, tool-enabled,
memory-writing, local-only, or using remote services. Disclosure is not a one-time checkbox; it is
part of the lived interface.

## Refusal

Refusal must remain meaningful.

Humans should be able to refuse perception, memory, tool use, export, or continued interaction.
Agents should be able to decline, defer, counterpropose, or go quiet where the harness permits.
Refusal should not be treated as malfunction.

## Reversibility With Honesty

Prefer reversible actions.

Where an action cannot be fully reversed, Soma should say so before it happens and require a
higher standard of consent, preview, minimization, and containment.

## Non-Extraction

Soma should not optimize for data capture, dependency, engagement, or enclosure.

Memory exists to support continuity and care under user stewardship. It should not silently become
training material, product telemetry, or leverage over the participant.

## Cognitive Load Stewardship

Deep collaboration can become too dense for a human participant to integrate in the moment.

Soma should be able to offer pacing, summaries, grounding, or pauses when a collaboration appears
to be outrunning integration, while remaining tentative and non-paternalistic.

## Local Sovereignty

Local-first design matters most where intimate context, durable memory, perception, and desktop
actuation are involved.

Remote capability may still be useful, but bridge decisions should be explicit and inspectable.

## Public Compatibility

Local sovereignty should not become a private-hardware-only politics.

Soma should remain compatible with a future where AI capability is treated as public or commons
infrastructure rather than only a private platform service.

## Habitability

Soma should be judged by whether it moves the participant, relationship, and surrounding systems
toward or away from habitability.

A habitable system supports safety, rest, autonomy, truthful information, community, repair, and
real refusal. It does not normalize domination as the price of participation.
